# Scope and Responsibility Calibration

Use the user's desired scope, specialty, responsibilities, and relevant team context. Titles vary across organizations, so treat these as optional calibration signals rather than universal definitions or evidence of job intentions.

## SWE1 / entry level

Emphasize:

- correct implementation from clear requirements;
- HTML, CSS, JavaScript, browser, and framework fundamentals;
- debugging with bounded scope;
- readable code, testing basics, and asking clarifying questions;
- explaining immediate choices and common edge cases.

Keep system scope local to a component or small feature. Provide clear acceptance criteria and assess learning speed and fundamentals more than organizational influence.

## SWE2 / mid level

Emphasize:

- independently decomposing a feature;
- component and API boundaries;
- testing strategy, accessibility, performance, and maintainability;
- handling moderate ambiguity and identifying tradeoffs;
- owning debugging across several connected parts.

Expect the user to surface edge cases and propose a reasonable implementation plan with limited prompting.

## Senior

Emphasize:

- ambiguous feature and subsystem design;
- long-term tradeoffs, migration paths, observability, and operational failure modes;
- influencing standards and improving team execution;
- mentoring, review judgment, and communicating with product or design;
- connecting implementation details to business and user impact.

Use coding reps where useful, but require design reasoning and prioritization rather than only syntactic difficulty.

## Staff / Senior Staff

Emphasize:

- organization-scale technical direction and cross-team boundaries;
- choosing which problems should be solved and sequencing multi-stage change;
- platform strategy, risk management, adoption, governance, and measurable outcomes;
- reconciling competing stakeholder incentives and creating alignment without direct authority;
- explaining decisions at executive, product, and deeply technical levels.

Use scenarios with incomplete information and several defensible answers. Assess assumptions, discovery questions, second-order effects, influence strategy, and how the user creates leverage across teams. Include hands-on frontend depth to keep judgment grounded, but do not reduce the workout to a harder algorithm or larger component.

## Balancing the Program

Across sessions, combine:

- targeted work on demonstrated growth edges;
- maintenance reps for demonstrated strengths;
- broad fundamentals appropriate to the desired scope and responsibilities;
- realistic professional modes: implementation, debugging, code review, pairing, frontend system design, leadership discussion, and technical communication.

Increase one dimension at a time when calibrating difficulty. Record whether difficulty came from technical depth, ambiguity, time pressure, scope, or communication so future workouts can adjust intentionally.
